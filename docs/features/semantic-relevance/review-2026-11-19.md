## Findings fixed

1. **P1 — Optional cache reads could prevent baseline fallback.** Cache reads
   inherited the shared 30-second DB connection timeout and had no SQL statement
   timeout. A locked embedding table could consume the API execution window
   before the exception handler could serve baseline. Cache reads now request a
   three-second connection timeout and a one-second statement timeout. Shared
   connection defaults and all baseline/event/operator callers stay unchanged.
   A real PostgreSQL exclusive-lock regression verifies baseline selection and
   event persistence while the embedding table is locked.

2. **P1 — Eager page hydration could discard all progress on a page.** Data API
   hydrated every subject before returning the page. A later large item reaching
   the deadline prevented already-read earlier items from being refreshed at all.
   The adapter now yields one hydrated subject at a time, and the worker persists
   it before reading the next. Regression tests reproduce the old zero-write
   failure and verify that the first subject survives a later interruption.

3. **P2 — Data API socket timeout was shorter than server execution time.** The
   worker used a ten-second timeout for both services. Data API can still be
   executing SQL after that point, so retries could repeat in-flight statements.
   Its read timeout is now 60 seconds; Bedrock remains ten seconds. The existing
   90-second reserve and checks before each attempt still protect worker shutdown.
   No `continueAfterTimeout` or transaction spanning inference is introduced.

4. **P2 — Invalid evaluation fixtures could produce misleading quality metrics.**
   Duplicate candidate IDs could push NDCG above one; a string `"false"` bypassed
   real-fixture model checks by being truthy; naive item timestamps made tie order
   dependent on host time zone. The evaluator now checks unique nonempty subject
   IDs, boolean mode, aware timestamps, valid available time, and positive known
   durations before scoring. Missing/bad embeddings still produce baseline fallback.

5. **P2 — Extreme numeric values and empty representations were mishandled.**
   Direct norm calculation could round tiny finite vectors to a nonunit result or
   overflow on large finite vectors. Scaling by maximum magnitude before computing
   the norm preserves direction. Empty normalized text now fails before paid
   inference/budget use and cannot pass semantic readiness through a matching
   cache hash. No representation/model version change is needed: the text contract
   and provider are unchanged.

Each finding has automated regression coverage. Existing eligible-pool selection,
soft duration behavior, diversity suppression, baseline/shadow semantics, public
response shape, domain entities, and Recommendation Event schema remain intact.

## Deployment readiness and remaining limits

The definitions retain the approved non-VPC/Data API architecture: regional
model-only InvokeModel permission, cluster/secret-scoped database authorization,
default-group/account-scoped Scheduler trust, two-hour cadence, concurrency one,
bounded retries, and migration-before-worker packaging/deployment order.

Local validation cannot establish deployed IAM/SCP/model access, regional Data
API behavior, account concurrency quota headroom, real corpus quality, or AWS
latency/cost. During a separately approved development rollout, verify the cache
migration, model invocation, repeat-run skips, and baseline/shadow behavior before
considering semantic activation. The Lambda Errors alarm has no notification
target and does not detect failures before Scheduler delivers the event; inspect
Scheduler delivery metrics as well as worker summary logs.

Bounded sweeps intentionally restart from the beginning and have no durable
traversal cursor. A very large/slow first subject, a scan that itself exceeds the
budget, or persistent failures consuming the generation allowance can delay later
subjects. This accepted small-corpus limitation is surfaced as failed/incomplete
work; addressing it at scale needs a separately reviewed checkpoint/queue design.
This review adds no AWS resources or new dependencies.
